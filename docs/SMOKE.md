# 真机冒烟清单（Smoke Test）

> 最近一次结果：[SMOKE_RESULTS.md](SMOKE_RESULTS.md)。

> 原则：**任何人都不需要把 memoQ 服务器、账号或项目内容交给维护者。**
> 维护者只在自己的测试实例上跑；使用者可在自己的服务器上跑同一份清单，只回报“通过/失败 + 脱敏错误”。
> 没有完成本清单的版本，只能以 Beta / Prerelease 发布。

## 0. 隐私边界

- 不截图包含客户正文的页面。
- 不提交真实项目名、文档名、GUID、URL、用户名、注释。
- 错误日志先脱敏：GUID → `<guid>`、项目/文档名 → `<project>/<doc>`、正文 → `<text>`。
- 只回报“哪一项失败 + 脱敏后的错误类型”，不需要开放服务器。

## 1. 测试环境

| 项 | 要求 |
|---|---|
| 环境 | 维护者自有测试实例，或使用者自己的服务器 |
| 项目 | 一次性测试项目，内容为假文本（不要用客户项目） |
| 文档 | 至少 30 行；含 tag、换行 tag、锁定行、已确认/已拒绝行 |
| 账号 | 有翻译 + 审校权限；不要用客户管理员账号 |

## 4. 发布判定

- 新版 N1–N15 全部通过，旧版 O1–O4 全部通过 → 可进入 stable 候选。
- 任一失败 → 修完重跑；无法真机验证 → 只能发 Prerelease，并在 Release notes 写明“未完成真机验证”。
- 没有测试实例的维护者：发 Beta，收集使用者按本清单的回执；至少 3 个独立环境通过后再考虑 latest。
