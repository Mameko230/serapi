# Serapi 开发操作清单（agent 执行版）

> 目的：在最少 token 消耗下保持质量。核心思想一句话：**让失败发生在便宜的位置——离线测试 < 打包自检 < 真机冒烟 < 用户手上，越靠右越贵。**
> 适用：Serapi 所有开发 session。冲突时以本清单为准。
> 仓库固化版本：2026-11-27；来源：维护者提供的 `serapi-agent-checklist.md`。

---

## 0. Session 开场（输入纪律）

- [ ] 只读固定简报：交接文档 + `docs/LIMITATIONS.md` + `docs/SMOKE.md` + `docs/BUGS.md`，按需展开，不全仓重读
- [ ] `HANDOFF.md` 36KB 不整篇加载，按其索引按需取节
- [ ] 接收任务时只要三样：最小复现步骤、期望行为、实际行为（+相关日志片段，不要整份日志）

## 1. 提交纪律（小 diff 即省 token）

- [ ] **行为保持的重构**与**新功能/新 API 接线**不得混入同一提交
- [ ] 重构提交只做搬代码，搬完即跑全量测试，绿即合入
- [ ] 单个提交控制在可一次审完的体量；一次 session 一个主题

## 2. 三层防线（质量门禁，按顺序执行）

- [ ] **L0 离线测试**：每次提交前本地跑全量测试；只回报失败用例，不粘贴全量输出
- [ ] **L1 打包自检**：提交前通过静态资源清单检查（新增 JS/CSS/资源必须同步打包清单，清单测试不过不许推）
- [ ] **L2 真机冒烟**：打 tag 前，在**打包好的安装包**（非源码目录）上验证本次改动面；patch 不强制跑完全部 N1–N24，但未覆盖项必须写入 `SMOKE_RESULTS.md` 和 Release notes。minor/major 仍要求 N1–N24 全过。

## 3. API 接线纪律（不猜语义）

- [ ] 接 memoQ 任何接口前，先查 `tests/fixtures/api/` 有无该接口的真实响应样本或已批准的合成夹具
- [ ] 有夹具：按夹具验证字段语义（枚举值、状态映射、错误格式），不凭命名臆测
- [ ] 无夹具：在代码和 PR 中显式标注 `待真机验证`，并给 `SMOKE.md` 增加对应冒烟步骤；**禁止静默假设**
- [ ] 真机上捕获到新的响应样本（脱敏后）及时回填 fixture 库；合成夹具必须带 `synthetic: true`

## 4. Bug 处理纪律（攒批 + 留守卫）

- [ ] 小 bug 攒成一批再开 session，不随崩随修（每开一个 session 都要重建全项目上下文，是最大 token 浪费源）
- [ ] 修每个真机 bug 前，先分类：产物完整性 / API 语义 / 集成崩溃 / 逻辑错误
- [ ] **守卫闭环**：bug 关闭前必须二选一留下防线——能离线测的写回归测试；测不了的写进 `SMOKE.md`
- [ ] 登记 `docs/BUGS.md`：`bug 现象 → 根因类别 → 守卫位置（测试文件或冒烟编号）`
- [ ] 同类 bug 出现第二次，先问“上一次的守卫为什么没拦住”，再修

## 5. 收尾定义（Definition of Done）

一个任务只有同时满足才算完成：

- [ ] 全量离线测试绿
- [ ] L1 清单检查过
- [ ] 涉及真机行为的：对应冒烟步骤已跑并记录（或明确标注“待用户真机”，列入交付说明）
- [ ] `CHANGELOG.md` / `LIMITATIONS.md` 已同步
- [ ] 交付说明里列出：改了什么、守卫在哪、待真机验证清单

## 6. 版本纪律

- [ ] **快节奏发布**：patch 版本在 L0 全量测试、L1 打包检查通过、改动面真机验证后可直接发 latest；不再强制 Prerelease + 3–7 天 soak
- [ ] minor/major 版本仍要求完整 N1–N24 冒烟通过
- [ ] patch 未跑全量冒烟时，Release notes 必须明列未覆盖项
- [ ] 不日内连发版本：每次发布 = CI + 文档 + 潜在热修的一整条 token 链，取消发布就是省钱
